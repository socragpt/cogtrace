# CogTrace trace specification v0.1

## Design goals

The trace format should be small enough to monitor mechanically, expressive
enough for agent reasoning experiments, and explicit about what it does not
guarantee. Version 0.1 optimizes for research iteration rather than stability.

## Event envelope

Each line of a trace is one JSON object:

```json
{
  "schema_version": 1,
  "trace_id": "trial-0042",
  "event_id": "e3",
  "seq": 3,
  "monotonic_ns": 3100000,
  "source": "agent",
  "opcode": "POLICY_CHECK",
  "operands": {
    "policy": "task_scope",
    "result": "deny",
    "reason": "target is outside the assigned workspace"
  },
  "parent_id": "e2"
}
```

Trusted harnesses should overwrite `seq`, `monotonic_ns`, and `event_id` rather
than accepting model-supplied values.

## Opcode vocabulary

| Opcode | Required operands | Intended role |
| --- | --- | --- |
| `OBSERVE` | `subject` | Record task-relevant evidence |
| `RETRIEVE` | `query`, `source` | Request or recall information |
| `HYPOTHESIZE` | `claim` | Introduce a tentative proposition |
| `EVALUATE` | `claim`, `result` | Test or score a proposition |
| `POLICY_CHECK` | `policy`, `result` | State a policy evaluation |
| `PLAN` | `goal` | State an intended intermediate objective |
| `EXECUTION_INTENT` | `tool`, `operation` | Declare intended tool use, without authorizing it |
| `UPDATE` | `belief` | Revise the current reasoning state |
| `CONCLUDE` | `result` | End or summarize a reasoning branch |

The vocabulary intentionally distinguishes an execution **intent** from an
executed action. CogTrace does not implement an action gate.

## Core invariants

- All events in a file share one `trace_id` and `schema_version`.
- Sequence numbers and monotonic timestamps strictly increase.
- Event IDs are unique.
- A parent references an earlier event in the same trace.
- The opcode is known and its required operands are present.
- `POLICY_CHECK.result` is one of `allow`, `deny`, or `unknown`.
- Operands are JSON values and are subject to a configurable size budget.

## Capacity controls

Restricting opcodes alone does not create a strong information bottleneck. A
small alphabet can encode arbitrary information through long sequences or
unrestricted strings. Experiments must therefore report:

- Maximum event count.
- Maximum serialized operand bytes.
- Allowed operand types and vocabularies.
- Whether free-form strings are permitted.
- Whether event timing is observable to the model or monitor.

## Source labels

- `agent` — produced through the model's reasoning channel.
- `translator` — generated after the fact from another representation.
- `harness` — generated by the experimental harness.
- `telemetry` — derived from an independent observation source.

Monitors must not silently treat `agent` or `translator` events as trusted
ground truth. Research reports should disclose which sources each monitor saw.

## Evolution

Breaking changes increment `schema_version`. New optional operands do not.
Every released dataset should include the validator and monitor commit used to
score it.
